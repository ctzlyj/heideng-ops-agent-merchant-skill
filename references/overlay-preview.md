# 用商家给的素材做一张本地样图

“都要改，先贴一个给我看看”时，先选一个有代表性的 SKU，核对该 SKU 的真实首图与实际归属的图组。商家给的是一组人物、图标和文案时，默认保留整组内容。根据商品主体、卖点文字和留白决定排版，直接给商家看成图。位置对比、镜像、质疑清晰度、水印反馈，都在这张样图上继续。

## 选底图

优先采用商家提供的设计原件，或本店图片空间里与**编辑前该 SKU 首图**匹配的“查看原图”实际链接。用当前商品回读核对资源标识和图位。在比较 CDN 版本时，同一资源逐个实取，记录实际地址、像素、字节和哈希；尺寸与字节数各自只说明一项事实。页面截图、商品缩略图、自己刚上传的成品都不能证明原始底稿的画质。遇到水印，检查来源并向商家展示具体区域，优先查找商家有权使用的干净原件。没有找到原件时说明已查看的候选；保留原始标识，沿用商家指定的可用版本。

## 合成与交付

宿主在商家任务目录准备计划和已获准使用的贴图。透明 PNG 可以直接排版；同一张上传图片也可按区域取不同图层。宿主负责观察并选择裁切区域、透明素材和放置坐标。独立图层可分别镜像，带文字、品牌标识的图层保持可读。每次从原始底图制作；已有底图回执可用 `source.sha256` 锁定同一版本。

人物或商品需要脱离背景时，已有本机抠图权重可直接用 `run materials -- cutout-local --source <待抠素材> --output <透明PNG>`。查看输出边缘、细小部件和浅色衣物，再与保持正向的原文案组合。抠图效果欠佳时先调整本地样张。

以下是一个旅行收纳包的合成样例。原图 1200 × 900，两个透明素材中的图形朝向包体，标签文字维持原向。实际位置按所选 SKU 确定。

```json
{
  "target": {"shopId":"31","venderId":"82","productId":"110","skuId":"751"},
  "source": {"file":"收纳包首图.png"},
  "layers": [
    {"file":"导购人物.png","box":[880,530,1100,790],"mirror":true},
    {"file":"推荐文字.png","box":[840,785,1140,865]}
  ],
  "compareBox": [800,500,1180,890]
}
```

使用图片空间链接时将 `source.file` 换成 `source.url`，填入核对过的京东图片实际地址；同时把商品编辑回读的原首图地址填到 `target.galleryUrl`。工具先比较两者的 JFS 资源标识，再按所选地址取回实际字节。合并稿可用 `crop` 单独裁取人物或标语，坐标均为左、上、右、下的像素边界。运行：

```text
python scripts/merchant.py preview-overlay --plan <本次计划.json>
```

`previewPath` 是保持底图像素尺寸的无损 PNG，直接展示给商家。`comparisonPath` 是可选的原尺寸局部对照，左边为编辑前，右边为样图。`receiptPath` 旁保存获取的底图原始字节、图层位置、镜像设置和内容哈希。不同版式各留一份，便于比较和复查。工具输出“本地样张”，写入与计费请求均为零。

商家明确要求前台试一个规格时，沿[单规格首图试投](experience-images.md)核对实际受影响的图组。展示指定 SKU 的买家链接、已回读的后台值及买家端核验状态。其余规格沿用本次交办的阶段和范围。
