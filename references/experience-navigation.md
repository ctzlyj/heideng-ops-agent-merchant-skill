# 经验导航：问题与工具不是一张白名单

本页只帮助宿主 Agent 找到经验；无需先做关键词匹配，也无需把整个目录装入上下文。用户意图决定规划，当前官方契约和真实授权决定可执行动作。

## 按事实选择资料

| 当前问题/事实 | 加载经验 | 常见组合 |
|---|---|---|
| 新店、店名不确定、旧授权疑似过期 | [连接](experience-connection.md) | 所有店铺模块共享同店身份 |
| 商品信息分缺口、短标题/白底/透明素材问题 | [内容](experience-materials.md) | 内容→图片；已有图可先核用途再上传 |
| 原链接、本地素材、实拍照片要变成新商品 | [上新](experience-listing.md) | 采集→上新→图文→内容；不必一轮全部做 |
| 改视觉、详情风格或图像落位 | [图文](experience-images.md) | 诊断定位→图文修复；不必重发商品 |
| 只要素材和真实价格、不上架 | [采集](experience-collection.md) | 采集→比价或素材交付，不能自动发布 |
| 同款同规格、价格策略、已确认调价 | [比价](experience-comparison.md) | 采集证据→比价→原改价；分析不授权写入 |
| 经营异常、广告低效、指标口径冲突 | [诊断](experience-diagnosis.md) | 诊断→内容/图片建议；没交办就不执行建议 |
| 已有成片/封面，需要交接或绑定 | [视频](experience-video.md) | 上新结果→视频；不需要先配 AI 生成渠道 |

## 组合例子（经验建议，顺序可调整）

- “把全店商品信息分维护好”：先核店并冻结范围。用素材交接中的独立短标题入口先提交免费成果，同时准备图片与属性证据。独立短标题和全量入口共享同一任务归属。原回执不明时先恢复，待审不计入已生效。
- “做到哪了？继续。”：用已核验 shopId 和 venderId 调用 `task-context --shop-id <shopId> --vender-id <venderId>`。按原任务和计划哈希选择回执。有同店多笔未完任务时，结合用户目标消歧。
- “最近退货多，广告也花得多，先改什么？”：按同店、同商品、同时间窗对齐广告和成交；从商家提供的脱敏记录归纳客服疑问及退货原因。用实际素材回执区分已上线变动与待审变动，把证据和建议交给商品运营。 [客服与售后协作](experience-service.md)

- “这些照片做成能上架的商品，把图和信息分一起弄好”：先读取实拍商品事实与目标类目；可用现成合格图就不生成；组合上新、图文与内容。准备完成不等于发布；同店同范围的已批准动作不再层层索要相同确认。
- “店里有些商品看起来不专业，顺便看一下广告为什么亏”：先辨清视觉问题与广告口径，按可取得数据并行分析；不强制先修全店图片，也不凭广告 ROI 推断利润。
- “想查一下这批商品有哪些库存问题”：即使目录没有“库存”模块，也查当前官方可用 Skill/接口，用本商家隔离环境读取；原包装器没有该 capability 只是包装器限制。
- 用户只要只读分析且没配生图：继续可用的只读路径；仅在任务真正需要新图时提出 Key、范围与预算缺项。

## 可选执行路径

1. 包内成熟包装器：按 [CLI 环境](merchant-cli-environment.md) 使用 status/run 和登记入口，来源/哈希保护不变。
2. 当前官方 Skill + 本商家 jdo-cli：查官方当前契约，使用商家环境与明确 Profile，核对目标店铺。目录外动作仍受相同写入/费用/恢复边界。
3. 宿主现有工具或商家任务目录局部脚本：用于数据整理、计算、网页已授权操作等；不得写入受保护 mature、伪造平台回执或绕过身份。

先读 [规则分层](execution-policy.md) 区分“通常如此”与“不能越过”。缺一条路径不等于全部任务不支持；没有合法可行路径时才报告具体阻塞和可交付部分。

## 来源与维护

各模块页标注原成熟来源版本、适用条件、实际执行入口与完成证据。案例描述不是平台永久规则；旧固定月份、旧店铺参数不自动继承。公共经验在包外层维护并随新版本分发；商家私有记忆、任务配置、结果和凭据留在状态/任务目录，不进入发布包。受保护源码的 provenance 是执行来源，不是宣称宿主能力已穷尽的许可表。


## 商家任务短指南（先读这里）

- 连接：已有授权直接复用；新店只需在打开的京麦页选择登录方式，等待核店结果。网络中断或等待超时后同店默认恢复，不主动“重新开始”。
- 素材：先说清店铺与全店/单商品范围。宿主先盘点、宿主写文案，工具生成/上传/绑定；审核中不是失败，离开后可从原任务查看。
- 结果只看四个数：已完成、审核中、需本人处理、结果未确认。完整回执在任务目录，不需要商家读技术JSON。
- 长任务可离开，恢复时带原任务目录；重复运行不是恢复，未知提交先核对，不重发。
- 需要额外模型/费用时单独说明；只读、已有素材或本地交接不因未配置外部视频/视觉渠道而停止。

技术参数与历史适配记录放在各模块页后半部分，宿主先按当前目标和真实工具返回规划，不把经验页当固定脚本。
## 新对话续办商品任务

商家说“继续昨天的样图”“接着改那条链接”时，先解析已核验店铺，再运行 `scripts/merchant.py task-context --shop-id ID --vender-id ID`。宿主按业务目标使用 `--goal listing|sample|creative|sku-edit|materials`；已知上架后的商品用 `--product-id`，已知复刻来源用 `--source-product-id`。多条同款结果按原商品链接、样张、任务编号区分。仍有多笔符合时，只请商家选择目标。保留原任务目录、原额度与请求回执。对未知生成、上传或发布先沿原任务只读核对；需追加计费时沿用正式确认入口。
