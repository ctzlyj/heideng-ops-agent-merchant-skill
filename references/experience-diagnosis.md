# 商家经营与广告诊断（外层适用提炼）

## 先确定问题、窗口和口径

适用于本店经营异常、流量/转化/货盘/广告效率诊断。需要实际店铺身份、商家有权限的京麦/商智/京准通或用户提供报表、明确时间窗口、同口径对照期及平台字段含义。

日期由当前任务/用户问题确定；不自动采用来源文中的固定历史月份或某店样本。期间、全店/商品/部门、有效/下单、现金/红包与去重方式写入任务说明。缺数据写缺项和影响，既不能补0，也不能把部分报表说成整店全量。

## 商家可用的取数路径

1. 本店官方京麦 CLI 原 L1 固定只读能力与基线回读。
2. 本店已授权商智/京准通：原 make_plans → sz-fetch/jzt-run → validate_report，沿用接口参数/归因/报告证据。宿主实际 owned 浏览器与商家环境，不借员工身份。
3. 无相关平台权限时可继续分析用户实际提供的报表；明确覆盖范围/口径/缺项。宿主有其他商家已授权官方能力也可使用，不以本包装器目录未命中拒绝。

**EasyBI、黄金眼、员工 GE/部门数据集、C+A内投核验、采销协同和内部发布不是本商家工具。** 保护快照里的旧说明只作来源背景；不能运行其员工命令、照搬固定数据集ID/日期或把内部渠道当缺项fallback。

## 原经验中适用于商家的判断

- 有效成交与下单金额分开；商品件数、父单量和客户数不是同一分母。商智客单价按成交金额/成交客户数；不要直接对比来源中员工系统采用件数分母的同名指标。
- 区间UV是去重值，日UV加总用于趋势，不能冒充区间UV；商品访客与店铺访客、来源浏览量也不同。
- 同端同窗口计算 CTR=点击/展现、CPC=花费/点击、广告CVR=对应广告订单/点击、广告ROI=同口径广告成交/花费。ROI不等于净利润；现金/红包和售后退款影响需先核对。
- 聚合比率通常按分子分母各自加总再相除，而非逐SPU平均。分母0/缺失报告未定义/数据不足，不造效率。
- 建议从货盘/流量/转化/广告漏斗定位，再按实际权限和问题深入计划/产品线/关键词。缺行业同类目基准时不拿全店或别类目填空；没有成本/补贴账单不能断言亏损金额。
- 观察异常后的建议可以组合 [内容](experience-materials.md)、[图文](experience-images.md) 或 [比价](experience-comparison.md)；用户只交办诊断就停在建议，不自动调价/改图/投广告。

这些是判断依据和可调整工作法，不是所有报告必须写满所有板块的强制模板。平台广告/稳赚机制按当期商家已授权规则读取，不能把历史京喜分层/阈值用于所有POP店。

## 原工具与完成证据

`run diagnosis -- <原L1参数>`；登记 `scripts/make_plans.py`、`scripts/sz-fetch.js`、`scripts/jzt-run.js`、`scripts/validate_report.py`。目录外官方取数见 [商家环境](merchant-cli-environment.md)。

交付可追踪的日期/字段/数据源/覆盖范围、同源报告与表格、派生计算和实际报告校验；区分观察、解释与建议。原报告校验没有执行则如实写未校验；通过结构/静态校验不证明真实经营结论。

## 来源与适用限制

整理自实际内部调度的 jd-store-diagnosis-skill 0.2.0 / 42971c0，原 [metric-dictionary](../mature/diagnosis/references/metric-dictionary.md) 的商智/京准通口径与原 L1/L2 源码。full-diagnosis-matrix/旧diagnosis说明中的员工字段、固定历史月份不作为商家运行说明；不整段复制原SKILL的内部安装/模型/身份流程。

本轮没有商家平台访问、账户口径或诊断结论实测。行业/归因窗口等必须以当前实际可取字段为准；公共经验与平台当期契约冲突时先核对官方资料，不删身份和真实性保护。
