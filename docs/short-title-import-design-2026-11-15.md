# 商家短标题自动导入设计（2026-11-15）

原目标保持：商家只描述目标，Agent读取完整在售/兄弟SKU，准备真实短标题，一次明确范围批准后自动上传/创建导入任务、查询原任务与逐行结果、原范围回读，不让商家手动导表，不把文件当成功。本轮不做真实授权、网页操作或店铺写入。

## 来源核对与取舍

只读参考本机jd-material-pop的短标题文档和pop_browser实现：公开商家商品页的短标题抽屉、file.upload、batchJobService.createImportJob/queryByPage。未找到可验证的官方CLI短标题写卡，因此不猜REST接口。参考只能选择性适配；员工profile、Cookie、Key、O2依赖、内网模型/运行状态与缓存模板均不迁移。

缓存模板的A2/B2是SKUID/短标题，说明上限30加权字符，并非内部建议16–30。公开规则页未成功获取，缓存不是当前平台实测；完整入口应从任务自有商家浏览器取得当次模板并核对。规划层先用保守1–30加权（汉字/全角字符计2），不支持无批准清空；16–28仅文案建议。新稿去重是设计的质量约束，不冒称平台硬规则；未知原短标题、全店原标题去重和审核状态不能被虚构。

## 分阶段接口

### A：完整规划与模板编译（本轮实施）

ShortTitlePlans读取原ShopMaterialAudit的完整稳定库存与完整health来源；重新从原health条目推导hasShortTitle，不信任独立派生布尔标志，不用有分数SKU当库存，不因素材段失败阻止已知标题规划。捕获全部在售SKU及离线兄弟，原父关系/名字/状态和原源审计指纹。只有在售、原健康条目明确标题问题、实际名字已知的SKU才接宿主审核的新稿；未知/无问题/离线/待文案完整报告，不能只展示选中行。

新增short-title-plan/status/rows。此阶段只有本地规划，writeExecutionAvailable=false；不能approve/execute，也不宣称当前原标题已验证或已导入。未来导入计划必须重新冻结浏览器模板与精确文件hash、解析行/批次，并复查全目录与标题问题，不把规划指纹当写许可。

模板编译只消费商家当次取得的模板或测试合成模板，不把内部缓存xlsx打包。标准库验证ZIP/XML，拒绝宏、外部关系、DTD/实体、重复/穿越条目、爆量、错误表头/公式与未知多工作表。保留前两行/格式/其他安全部件；移除示例数据及不再引用的sharedStrings，SKU始终inline文本，按5000分块和5MB检查，不截行。输出是Agent的中间产物，不作为默认人工导入交付；templateOriginVerified=false，下一阶段取得独立网页来源证明才可写。

### B：任务自有浏览器与原件（后续立即接入，不省略）

复用独立BrowserRuntime及身份JSON证明设计，新建商家状态内独立Chrome/Edge profile，不借用员工/工作浏览器，不复制Cookie。每个浏览器调用复核同一JSON对象的shopName/venderId/shopId，收集当次可信任务列表/模板证明，响应/DOM原文及签名URL不落日志或回复。

根批准绑定原完整审计、标题稿、实际模板/文件/行hash、当前browser来源与批次。上传/点击前独立attempt与统一截止时间；上传URL需要持久恢复时只用OS受保护存储，不能明文保留。限定短标题抽屉input，上传一次并确认createImportJob业务响应；只接受当次原响应/确切上传源关联的实例ID，jobId=任务类型不当实例ID。unknown仅查原任务，不能换工具重传/重点击。

### C：逐行结果、原范围验证与安装验收

计数和已知行结果分开；只从当次实例的完整结果表识别确认失败SKU，允许同一原范围只修这些失败行，未知或审核延迟不重投整表。成功行不代表生效；健康flag清零只是该原生来源的观测，真实原标题/审核与门户信息分仍需独立核实。全范围和剩余未知状态均分页。最终安装/回滚门禁涵盖所有阶段原件与孤立证明，实际私有GitHub重装后验证。真实merchant/OAuth/类目/许可另获允许才验收。

## 约束

所有开发测试仅合成店铺/身份/API/模板；不调用真实jdo info、OAuth、商家网页、写入、消息或任何模型。本轮A完成不等于短标题自动导入完成，更不等于整体goal完成。生图/视频来源待用户选择，内部版和个人Skill保持只读。
