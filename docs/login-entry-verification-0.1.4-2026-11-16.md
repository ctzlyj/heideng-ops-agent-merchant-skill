# 0.1.4 开发检查点：HD-002 实际登录入口修复

日期：2026-11-16（Asia/Shanghai）。上一源码基线：586dde2bc571fa31ddb16ef4edca0ecdc9762b52。候选应取包含本文的 0.1.4 提交，不是旧基线。

## 根因与最小改动

0.1.3 的宿主 open_login 仅传店名，未明确登录地址；旧独立浏览器仍 goto 京麦首页，提示也保留“先点击登录”。因此上一轮不能将 HD-002 记为完整修复。

本次复用已有浏览器导航和同会话能力：
- 未登录任务的 open_login 明确携带公开 URL `https://passport.shop.jd.com/login/index.action`，Agent 控制器必须直接执行该 URL，不忽略后回到首页。
- 原独立 Playwright 导航也改用同一个登录地址；不是只改提示。
- 已登录且归属、身份已验证的任务会话仍复用，不导航回登录页，不重新扫码。
- 登录后仍在同 context 观察工作台身份并衔接原官方 OAuth。不信任 passport 的会话数据作为店铺身份，不读取或导出 Cookie。
- 仅修实际入口、提示、版本与相应验证；生图、上架、短标题等成熟业务未改。内部版与原 0.1.1 ZIP 未动。

## 实际验证

- 新入口回归先在旧实现得到 3 个预期失败：host 动作没有 URL、独立浏览器打开首页、提示要求额外点击登录；修复后通过。
- 真实 Edge/控制器测试先确认旧执行器忽略 URL 会失败，再验证新执行器实际首屏是登录页。
- Git 暂存区冻结源码的 112 项相关回归全部通过，包含入口、宿主连接、身份确认、同窗 OAuth、官方 CLI 隔离、脱敏和安装/分发/升级。
- 真实 Edge、真实控制器子进程、所有页面请求拦截的 smoke 通过：直接 passport 登录页；合成登录完成后同会话复用，不返回登录页；非旧白名单测试工作台身份可观察；同实际 context/page OAuth 导航、合成官方回执核对和归属清理通过。
- 临时 0.1.4 包构建/审核通过：123 个清单文件；含清单共 124 个文件；个人路径、凭据模式和未知文件均为 0。
- 原 0.1.1 ZIP SHA256 保持 `7cf2d935cd50e652727883ba6b6cab8d0731c7e56c7424b878600ca843b61b34`；内部版 HEAD 保持 `13692b759bd52e35c3670cf8fad5330e1bf2b576`，工作区无修改。

## 边界

这是实际浏览器导航的拦截测试，不是商家真实扫码或令牌签发；不宣称 HD-008 或整个授权已在现网关闭。已有任务控制器如忽略 open_login.url，Agent 必须按新契约修正该任务局部适配，不能继续沿用首页硬编码。没有改运行中的授权任务、导出凭据、店铺写入或付费模型调用。

只推送开发分支，不创建 Release、不替换发行 ZIP、不通知商家更新。
