# 商家实测可用性修复 Implementation Plan

**Goal:** 宿主 Agent 规划；黑灯提供经验导航和真实可达的成熟工具。只修商家实测卡点。
**Architecture:** 保持 mature 来源与原授权、回执、导入机制。外层仅做安装/解释器/安全输入适配；内部修范围与官方响应衔接。
**Tech Stack:** Python、官方 jdo-cli、现有 Playwright、现有签名分发。

## 不变量
- 基线 b5b4a275 / 0.4.0；旧目录、内部版、个人 Skill 不写。
- `_shared_image_rules`、`image_prompt` 源码原样；商品本体文字驳回走原申诉，不擦字/重复付费重生。
- 不实际扫码、店铺操作、付费生成；只验证本轮改动。
- 不创建业务调度引擎、额外审批状态机；不改写未知回执为成功/未提交。

## 实施拆分
- [x] 范围和参考：局部失败测试→低分复用真实槽位核对；冻结计划允许同店子集；修复/属性/回读限定同集合；官方详情主图兜底与公共图片请求头。
- [x] 环境与浏览器：失败测试→默认核心依赖、WorkBuddy独立安装路径、既有3.12解释器发现透传、付费前桥接预检；复用同店登记浏览器类型。
- [x] 输入与恢复：失败测试→安全密码页回退、明确选择系统安全记住Key、只读不弹窗；OS执行锁与遗留锁检查；错层对账报错；stdout摘要+完整任务文件。
- [x] 导航与交付：宿主事实依据/属性缺口说明、单商品不扩大费用；更新 provenance 商家哈希，保持来源；提示词AST锁验证；新版本签名固定包、提交推送默认分支。

## 证据边界
商家对话测试版本0.3.0。建议页标题可访问、正文401，未独立读取全文；仅采用对话中可见建议且经源码确认的问题。离线测试不是跨宿主或真实商家验收。
