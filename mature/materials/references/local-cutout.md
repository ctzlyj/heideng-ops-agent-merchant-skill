# 本地商品抠图引擎（2026-10-30）

## 默认与边界

**效率第一（2026-10-30用户决定）**：`make_transparent(..., quality='fast')`是默认，常规新增透明图用旧颜色泛洪算法快速本地生成，不加载模型。只有被驳回的透明图才在`repair-rejected`里调用`quality='neural'`，即`rembg==2.0.85` + 固定SHA256的`birefnet-general-lite`。标准版`birefnet-general`和`--alpha-matting`供离线对比/疑难图；没有实测收益时不要无条件升级大模型或精修。

- 只消费已经确认的800×800商品源RGB，输出同尺寸RGBA PNG≤3MB，**只采用模型alpha，原商品RGB逐像素不改**。分割模型不是生成模型，不调用付费网关。
- 同进程复用一份模型会话，CPU默认4线程、最多1个推理/精修任务，和20并发网关池独立限流。切换标准模型会释放旧缓存，不保留多份大模型占内存。
- 神经修复的下载/推理失败明确`prepare-required`或质量错误，**不静默回退**旧算法重投驳回槽位。模型缺失只阻塞驳回透明修复，不阻塞常规快速维护。旧算法可能误删白色印刷/白色主体，常规上传前依旧检查；平台以“抠图损坏”驳回后进入神经修复。
- 这只负责前景分割，不能替你选择SKU/商品。有人体、道具、行李箱、营销拼图的源图先修正，再抠图；不要把保留人物的算法输出当作商品合格图。
-白色电泵/反光产品仍可能有边缘漏抠；透明PVC/孔洞/线环、实际多件组合必须深浅底色预览。明确可靠源与前景轮廓仍是疑难兜底，不用任意凸包处理所有图案或凭空猜几何。

## 上岗与离线命令

```powershell
python -X utf8 scripts/jd_material_agent.py prepare-cutout --download
python -X utf8 scripts/jd_material_agent.py cutout-local --source <white800.png> --output <new-transparent.png>
python -X utf8 scripts/jd_material_agent.py cutout-local --source <white800.png> --output <other-new.png> --model birefnet-general --alpha-matting
```

`pop_setup.py --install-missing`会补齐依赖并准备校验默认权重；`--check-only`不下载权重，但会离线校验已有缓存SHA；轻量inspect/doctor只报告存在，不把存在冒充校验通过。`pop_doctor`只读报告依赖/模型缓存，不初始化推理、不发业务请求。

执行驳回透明修复时不会临时下载模型。缺失权重先执行prepare；改版后其他未上传缓存图片不会被自动抹掉。已通过/审核中素材不因换本地抠图后端重绑。

每个新PNG旁保存`.cutout.json`，包含原图SHA、模型SHA、配置、输出SHA和质量统计。再次同输入同配置同结果复用；原图改变、用户编辑PNG、丢失回执或不匹配的旧文件都停止，不覆盖。未知上传/绑定继续遵守原有精确对账，不因重新抠图清账。

## 包、模型与许可

包固定rembg2.0.85，不用它的默认BRIA模型。仅允许两份明确BiRefNet工件，SHA见`cutout-license-sources.json`与代码allowlist；缓存与权重不进入Skill/Git。首次准备约214MiB Lite或928MiB标准版。上游代码、模型作者和ONNX模型卡2026-10-30均标注MIT，来源URL和原文hash已记录；不是保证所有训练素材都无第三方限制，也不把代码许可自动外推给其他模型。

模型质量基准用实际失败类样本和已审核通过的明确人工alpha作对照；离线像素指标不等于新算法输出已经过京东审核。不重投已通过素材来证明吞吐，不把历史16秒/张当今天实测。

## 2026-10-30重新对比（非平台自动验收）

6类真实样本：白色印花袋、多件组合、白色电泵、PVC提带、浅粉袋、细导轨；前5类用已审阅且历史平台通过的手工mask对照。白色印花保留率旧泛洪28.8%，Lite99.04%；白色电泵对应白色前景旧法1.0%，Lite90.81%。Lite保住大部分主体，但电泵局部边缘与线环仍需要检查，不能宣传绝对无损。

Lite当前CPU6样本单图26–66秒（不含7.77秒会话加载），标准版选测3样本49–93秒（不含10.02秒加载），这是当前负载下观测，不是固定时延。标准版对白色印花/电泵未表现出稳定优势；Lite+matting质量样本也未稳定优于plain alpha，所以默认只用Lite，不强制每张精修。matting早期诊断重复推理过两遍，耗时不作为公平基准。详细指标见local-cutout-benchmark.json。

模型权重文件大小不等于运行内存。并行评估多个ONNX引擎曾引发内存分配失败：最终引擎禁用累计CPU arena/memory-pattern缓存、仅一份活动session、推理串行，失败释放会话并明确报错。不为了速度盲开20个CPU抠图进程，也不在资源不足时改用已知有损泛洪。

实际接入命令追加测试：关闭累计内存arena后，Lite连续3样本（白印花、多件组合、PVC提带）观测总墙钟约54秒，首次含session/图加载28.7秒，后两张12.0/13.0秒，同一会话复用；结果SHA与独立Lite对比一致。输出缓存二次复用，无推理；源RGB未变。这个数值不与后台负载不同的初测直接当作提速倍率。

安全边界：初始化从同一份已验证模型字节构建ONNX图，不调用rembg会再次下载的new_session构造器。源图hash和解码使用同一字节快照；输出PNG/回执对有专用文件锁与排他创建，用户修改/其他并发写者不被覆盖。rembg依赖探测检查具体2.0.85版本，不只看模块存在。
